# Block metadata, registration and build output

Contents: metadata baseline, asset fields, registration paths, build tooling, failure table, sources.

## Metadata baseline

```json
{
  "$schema": "https://schemas.wp.org/trunk/block.json",
  "apiVersion": 3,
  "name": "acme/notice",
  "title": "Notice",
  "category": "text",
  "textdomain": "acme-blocks",
  "attributes": { "message": { "type": "string", "default": "" } },
  "supports": { "interactivity": true },
  "editorScript": "file:./index.js",
  "style": "file:./style-index.css",
  "editorStyle": "file:./index.css",
  "render": "file:./render.php",
  "viewScriptModule": "file:./view.js"
}
```

- Name format is `namespace/block-name`: lowercase alphanumerics and dashes, starting with a letter. Renaming orphans every saved instance, so treat the name as a public contract.
- `apiVersion` 3 arrived in WordPress 6.3. WordPress 6.9 logs a console warning for blocks registered with 2 or lower and the published schema accepts only 3. Raising the value is a runtime change (iframe editor), not a cosmetic one. See [editor-and-iframe-compat.md](editor-and-iframe-compat.md).
- Fields with version gates: `render` 6.1, `viewScriptModule` 6.5, `viewStyle` 6.5, `blockHooks` 6.4, `selectors` 6.3, `allowedBlocks` 6.5 (metadata), `ancestor` 6.0, `variations` as `file:./variations.php` 6.7. Verify others against the target minimum before adding them. The metadata reference documents only `viewScriptModule`; there is no `scriptModule` field (confirmed 2026-10-08), so do not use one.
- Supports gated by version: `renaming` 6.5, `allowedBlocks` support 6.9, `visibility` 6.9. `supports.interactivity` is `true` or an object with `clientNavigation` and `interactive`.

## Asset fields

- Values are `file:./path` (relative to `block.json`), a registered handle (`wp_register_script`, `wp_register_style`, `wp_register_script_module`), or an array mixing both. Arrays are accepted for scripts since 6.1 (`editorScript`, `script`, `viewScript`) and for styles since 5.9.
- A `file:` asset gets its dependencies and version from a sibling `*.asset.php` that the build emits. A hand-copied JS file without it loads with no dependencies and fails with `wp is not defined` or `Cannot read properties of undefined (reading 'blockEditor')`.
- Frontend-only fields: `viewScript` (classic script), `viewScriptModule` (ES module, required for the Interactivity API because classic scripts cannot depend on modules), `viewStyle`.
- `render.php` runs per block instance. Do not declare functions or classes in it; a second instance raises `Cannot redeclare`. Put shared logic in an included file loaded with `require_once` or in the plugin.

## Registration paths

| Situation | Call | Gate |
| --- | --- | --- |
| One block | `register_block_type( __DIR__ . '/build/notice' )` on `init` | 5.8 |
| Many blocks, manifest generated by build | `wp_register_block_types_from_metadata_collection( __DIR__ . '/build', __DIR__ . '/build/blocks-manifest.php' )` | 6.8 |
| Many blocks, per-block args | `wp_register_block_metadata_collection()` then `register_block_type()` per folder | 6.7 |
| Need PHP-only args (e.g. `render_callback`) | `register_block_type_args` filter (5.5) or `block_type_metadata_settings` filter (5.7) | 5.5 / 5.7 |

Fallback for 6.7 and below:

```php
add_action( 'init', static function () {
    $manifest = __DIR__ . '/build/blocks-manifest.php';
    if ( function_exists( 'wp_register_block_types_from_metadata_collection' ) ) {
        wp_register_block_types_from_metadata_collection( __DIR__ . '/build', $manifest );
        return;
    }
    if ( function_exists( 'wp_register_block_metadata_collection' ) ) {
        wp_register_block_metadata_collection( __DIR__ . '/build', $manifest );
    }
    foreach ( array_keys( require $manifest ) as $slug ) {
        register_block_type( __DIR__ . "/build/{$slug}" );
    }
} );
```

If the same name is also passed to `registerBlockType()` in JS, the JS name must equal the `block.json` name; a mismatch yields a second, unrelated block.

## Build tooling (`@wordpress/scripts`)

- `wp-scripts build` finds `block.json` under `src/` and turns each referenced `editorScript`, `script`, `viewScript` into an entry. Output mirrors the folders under `build/`. `index.css` is editor-only; `style-index.css` is shared.
- `--blocks-manifest` writes `blocks-manifest.php` (flag added in `@wordpress/scripts` 30.14.0; 30.3.0 had a separate `build-blocks-manifest` command, per the package changelog). The manifest is only read by `wp_register_block_metadata_collection()` (6.7+) and `wp_register_block_types_from_metadata_collection()` (6.8+).
- `--webpack-copy-php` copies all PHP from `src/`; by default only files named by `render` and `variations` are copied.
- `--experimental-modules` is documented as experimental support for `viewScriptModule` (the README names no other module flag); confirm with `npx wp-scripts build --help` for the locked version before relying on it.
- `check-engines`, `check-licenses`, `lint-js`, `lint-style`, `test-unit-js` (Vitest since `@wordpress/scripts` 36.0.0, consumer-installed; earlier releases ran Jest, and `test-unit-jest` remains as an adapter), `test-e2e` (Playwright), `plugin-zip` exist; run only those the project configures.

## Failure table

| Symptom | Confirm | Fix |
| --- | --- | --- |
| Block absent from inserter | `wp eval 'var_dump(WP_Block_Type_Registry::get_instance()->is_registered("acme/notice"));'` in a disposable site; PHP notices on `init`; browser console | Correct path (build vs src), run the build, fix invalid JSON or name |
| `Block "x" is not registered` in the editor but PHP registers it | Compare the name inside saved markup `<!-- wp:acme/notice -->` with `block.json` | Restore the original name; add a transform if intentionally renamed |
| Editor script runs but controls missing | Network tab: `.asset.php` deps; console `undefined` globals | Rebuild so the asset file exists; use `file:` paths |
| Frontend script not loading | View source for the module id; `viewScriptModule` plus a rendered block instance | Ensure the block renders on the page and build emitted a module |
| `Cannot redeclare` fatal on second block | `render.php` declares functions | Move declarations to an included file |
| Styles missing in the editor only | Check iframe; `style` vs `editorStyle`, handles declared in `block.json` | Declare assets in metadata; see iframe reference |
